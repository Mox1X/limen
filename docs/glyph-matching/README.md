# Brightness и экспериментальный shape

Одинаковые геометрия, камера, источник света и начальный ракурс: локальный `Skull.obj`, объект `part_0`, поворот X = 180°, 120×40 символов изображения, 2×4 отсчёта, cell aspect = 0.5. Снимки фиксированы, без автовращения и строки статуса.

- [Brightness](brightness.txt) и [shape](shape.txt) с освещением.
- [Силуэт brightness](brightness-silhouette.txt) и [силуэт shape](shape-silhouette.txt).
- [Синтетические маски и выбранные символы](synthetic.txt).

В таблице синтетики обе диагонали имеют среднюю яркость 0.5: brightness выдаёт `+`, а shape — `/` и `\`. Горизонтальные штрихи одинаковой средней яркости 0.25 различаются как `-` и `_`. Это проверяет сохранение расположения значений внутри ячейки; воспроизведение собственных шаблонов не является доказательством улучшения изображения произвольного шрифта.

На черепе дополнительные штрихи появляются прежде всего на силуэте и на границах ярких и тёмных участков. Большинство ровных областей сохраняет обычные символы яркости. Не все новые штрихи визуально удачны: ручной атлас приблизителен, а реальная форма глифа зависит от шрифта терминала. Поэтому brightness остаётся стандартным режимом.

В shaded обоих вариантов используются contrast 1.2 и gamma 1. Brightness применяет коррекцию после усреднения ячейки, shape — к каждому из восьми значений до сопоставления, поэтому различаются не только штрихи, но и некоторые полутона на границах. Снимки силуэта используют линейное преобразование и позволяют сравнить форму отдельно от освещения.

## Измерения

Локальный Linux, Rust 1.98.0, release, 300 кадров каждого варианта, 31 016 невырожденных треугольников. Полный кадр включает рендер и ASCII; отдельное преобразование повторяется на готовом framebuffer исходного ракурса. Терминальный I/O, загрузка OBJ и запись снимков не входят в измерение.

| Режим | Полный кадр, мс | Только преобразование, мс |
| --- | ---: | ---: |
| brightness | 8.327 | 0.092 |
| shape | 8.221 | 0.295 |

Разница полного времени находится в пределах вариаций измерения; shape не следует считать более быстрым. Само преобразование стало примерно в 3.2 раза дороже, добавив около 0.2 мс на этом фиксированном кадре. Оба варианта укладываются в CPU-бюджет 33.3 мс для целевых 30 FPS в данном окружении.

## Воспроизведение

```sh
cargo run --release --example benchmark -- Skull.obj --object part_0 \
  --rotate-x 180 --columns 120 --rows 40 --frames 300 \
  --compare-glyphs --snapshot-dir docs/glyph-matching

cargo run --release -- Skull.obj --object part_0 --rotate-x 180 --glyph-mode shape
```

Нажмите Space для паузы, затем `M` для сравнения алгоритмов на одном ракурсе. `1`–`6` переключают диагностические режимы независимо от алгоритма глифов, а `0` восстанавливает параметры запуска.

`Skull.obj` остаётся локальным и исключён из Git. Атлас не требует TTF/OTF и не привязан к шрифту. В текущем эксперименте используются только печатные ASCII-символы; все TXT-снимки следует открывать без переноса строк и моноширинным шрифтом.

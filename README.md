# Limen

Собственный CPU-рендер 3D-геометрии в монохромный ASCII для терминала. Первая версия — просмотрщик OBJ с медленным вращением, фиксированной камерой и неподвижным направленным светом.

## Запуск

Нужны Rust/Cargo и интерактивный терминал с моноширинным шрифтом.

```sh
cargo run --release
cargo run --release -- path/to/model.obj
cargo run --release -- tests/fixtures/smooth.obj
```

Без файла показывается встроенный куб. OBJ центрируется и равномерно масштабируется до единичного радиуса. Загружаются все части файла; их взаимное расположение сохраняется. Нормали из OBJ дают сглаженную поверхность; если нормалей нет, используются нормали отдельных граней. Материалы и текстуры игнорируются, файлы MTL не нужны. Для предсказуемого результата на сложных вогнутых полигонах лучше экспортировать уже триангулированную модель.

Если вместо модели виден куб или другая закрывающая её геометрия, проверьте состав OBJ:

```sh
cargo run --release -- Skull.obj --list-objects
cargo run --release -- Skull.obj --object part_0 --rotate-x 180
```

`--list-objects` печатает имена объектов/групп и число треугольников до удаления вырожденных граней; терминальный режим не включается. `--object NAME` выбирает часть по точному имени; флаг можно повторять. Центрирование и масштабирование выполняются после отбора. Без `--object` по-прежнему отображаются все части. В предоставленном `Skull.obj` объект `part_1` — окружающий череп куб, поэтому для черепа нужен `--object part_0`.

Начальную ориентацию можно задать через `--rotate-x`, `--rotate-y`, `--rotate-z` в градусах (по умолчанию 0). Используется композиция `Rx * Ry * Rz`; затем автовращение применяется вокруг мировой оси Y. `R` сбрасывает автовращение к заданной начальной ориентации. Для предоставленного черепа `--rotate-x 180` ставит модель вертикально и поворачивает лицом к камере.

Управление:

| Клавиша | Действие |
| --- | --- |
| Space | Пауза / продолжение |
| R | Сброс угла поворота |
| Q, Esc, Ctrl+C | Выход |

Параметры:

```sh
cargo run --release -- model.obj --fps 30 --samples-x 2 --samples-y 4 --cell-aspect 0.5
```

- `--fps`: предел частоты кадров, 1–240, по умолчанию 30. Если рендер не укладывается в бюджет, фактическая частота ниже.
- `--samples-x`, `--samples-y`: 1–16 отсчётов по каждой оси на символ, по умолчанию 2×4. Больше отсчётов сглаживает границы и сохраняет вклад мелких деталей, но увеличивает затраты CPU. Итоговая детализация всё равно ограничена сеткой символов.
- `--cell-aspect`: ширина символа / высота символа, по умолчанию 0.5. Подберите под шрифт, если куб выглядит вытянутым. Плотность отсчётов не меняет пропорции проекции.

Размер кадра следует за размером терминала. На очень узком терминале часть модели может выходить за поле зрения. Ограничение в 16 миллионов внутренних отсчётов предотвращает чрезмерное выделение памяти; уменьшите sampling или размер окна при соответствующей ошибке.

## Конвейер

```text
OBJ / встроенная геометрия
  → преобразование модели, камеры и перспективная проекция
  → отсечение треугольников по шести плоскостям в однородных координатах
  → растеризация треугольников и проверка глубины
  → интерполяция нормалей с учётом перспективы
  → фоновый + ламбертовский направленный свет
  → усреднение яркости 2×4 отсчётов на символ
  → шкала « .:-=+*#%@»
  → пакетный вывод через crossterm
```

Глубина хранится на каждый внутренний отсчёт. Пустые отсчёты имеют нулевую яркость и участвуют в усреднении на силуэте. Нормали преобразуются обратной транспонированной матрицей модели. Обратные грани не отбрасываются: открытые поверхности OBJ тоже видимы, а их яркость определяется исходной нормалью.

Рендер не зависит от терминала. `geometry` описывает модели, экземпляры, камеру и свет; `render` заполняет framebuffer глубины и яркости; `ascii` превращает его в `CharGrid`; `terminal` выводит кадр. Приложение связывает ввод, время и размеры окна. Используется правая система координат: Y вверх, исходная камера смотрит вдоль −Z, глубина после проекции — от 0 до 1.

Терминальный слой использует отдельный экран, raw mode и белые символы на чёрном фоне, скрывает курсор на время работы. Кадр отправляется одним буфером без очистки экрана между кадрами. При обычном выходе, возвращаемой ошибке или раскрутке стека после panic терминал восстанавливается.

## Проверки и измерения

```sh
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo run --release --example benchmark
```

Тесты проверяют сетку символов, усреднение, общую границу треугольников, буфер глубины, отсечение, перспективную интерполяцию нормалей, загрузку OBJ и ошибки CLI. Небольшие OBJ в `tests/fixtures` созданы для этого проекта.

Benchmark рендерит 300 кадров куба и тестового OBJ при 120×40 символах и 2×4 отсчётах. Он включает перевод в ASCII, исключает терминальный ввод/вывод и печатает число треугольников, время кадра и FPS. Эти маленькие модели проверяют базовую стоимость конвейера; результат не является гарантией скорости на тяжёлой модели черепа.

Контрольный замер в локальном Linux-окружении, Rust 1.98.0, release-сборка:

| Модель | Треугольники | Время кадра без терминального I/O |
| --- | ---: | ---: |
| Куб | 12 | 0,327 мс |
| `smooth.obj` | 8 | 0,319 мс |

Дополнительно проверены через псевдотерминал: видимый вывод куба и OBJ, пауза, сброс, продолжение вращения, изменение размера, выход через Q/Esc/Ctrl+C и восстановление атрибутов терминала.

## Дальнейшее развитие

Композиция по мотивам «Сотворения Адама» — демо поверх этой основы. Сначала можно добавить статичный ASCII-фон рук, затем независимо вращающийся череп и слабую пульсацию света. Для объёмных рук с общим освещением понадобятся 3D-модели. Многопоточность, SIMD, тени, блики и восстановление сглаженных нормалей пока не реализованы.

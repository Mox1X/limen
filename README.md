# Limen

Собственный CPU-рендер 3D-геометрии в монохромный ASCII для терминала. OBJ-просмотрщик с медленным вращением, неподвижным направленным светом, настройкой яркости и диагностикой геометрии.

## Запуск

Нужны Rust/Cargo и интерактивный терминал с моноширинным шрифтом.

```sh
cargo run --release
cargo run --release -- path/to/model.obj
cargo run --release -- tests/fixtures/smooth.obj
```

Без файла показывается встроенный куб. OBJ центрируется и равномерно масштабируется до единичного радиуса. Загружаются все части файла; их взаимное расположение сохраняется. Нормали из OBJ дают сглаженную поверхность; если нормалей нет, используются нормали отдельных граней. Материалы и текстуры игнорируются, файлы MTL не нужны. Для предсказуемого результата на сложных вогнутых полигонах лучше экспортировать уже триангулированную модель.

Если вместо модели видна закрывающая её геометрия, проверьте состав OBJ:

```sh
cargo run --release -- Skull.obj --list-objects
cargo run --release -- Skull.obj --object part_0 --rotate-x 180
```

В локальном `Skull.obj` объект `part_1` — окружающий череп куб; `part_0` — сам череп. Модель не включена в Git. `--list-objects` печатает имена и число треугольников до удаления вырожденных граней, не открывая просмотрщик. `--object NAME` выбирает часть по точному имени; флаг можно повторять. Центрирование, масштабирование и кадрирование выполняются после отбора.

Начальная ориентация: `--rotate-x`, `--rotate-y`, `--rotate-z` в градусах (по умолчанию 0), композиция `Rx * Ry * Rz`. Затем автовращение применяется вокруг мировой оси Y со скоростью 6°/с. Для черепа `--rotate-x 180` ставит модель вертикально и поворачивает лицом к камере.

## Настройка изображения

```sh
cargo run --release -- Skull.obj --object part_0 --rotate-x 180 \
  --zoom 1.1 --light-azimuth -55 --light-elevation 35 \
  --ambient 0.06 --contrast 1.2 --gamma 1
```

| Параметр | По умолчанию | Диапазон / действие |
| --- | --- | --- |
| `--fps` | 30 | Предел частоты кадров, 1–240 |
| `--samples-x`, `--samples-y` | 2, 4 | По 1–16 отсчётов на ось символа |
| `--cell-aspect` | Авто | Ширина ячейки / высота, ручное значение 0.05–5 |
| `--zoom` | 1 | 0.5–3, увеличение относительно вписанной модели |
| `--light-azimuth` | −55° | 0° — к исходной камере (+Z), +90° — к +X |
| `--light-elevation` | 35° | −90°–90°, положительное направление вверх (+Y) |
| `--ambient` | 0.06 | Фоновый свет, 0–1; диффузный вклад равен `1 − ambient` |
| `--contrast` | 1.2 | 0.25–3, контраст вокруг средней яркости 0.5 |
| `--gamma` | 1 | 0.25–4, показатель степени; больше 1 затемняет полутона |
| `--view` | `shaded` | Режим изображения из списка ниже |
| `--glyph-mode` | `hybrid` | `brightness`, `shape`, `hybrid` |
| `--palette` | `structural` | `tonal`, `structural`, `full`; полный набор требует `--font` |
| `--complexity-penalty` | 0.01 | Штраф за сложность символа, 0–1; 0 отключает |
| `--stability` | 0.005 | Допуск удержания предыдущего символа, 0–1; 0 отключает |
| `--font` | Встроенный атлас | Путь к моноширинному TTF/OTF для всех алгоритмов |
| `--font-size` | 16 с `--font` | Размер в px/em, 4–128; дробные значения допустимы |
| `--font-cell` | Метрики шрифта | Ячейка атласа `WxH`, по 1–512 пикселей на ось |

Пропорции определяются по пиксельным размерам терминала и числу строк/столбцов. Не все терминалы сообщают пиксельный размер: тогда используется `0.5`. Явный `--cell-aspect` всегда имеет приоритет. Если модель кажется вытянутой, подберите значение под свой шрифт. Нижняя строка показывает величину и источник: `auto`, `manual` или `fallback`. Размеры проверяются каждый кадр, в том числе при смене шрифта.

Камера вписывает ограничивающую сферу модели с полем около 10% по более узкой оси. Одна строка отведена под статус; её высота исключена из aspect ratio изображения. Zoom меняет угол обзора, сохраняя положение камеры; увеличение выше единицы может обрезать силуэт. При resize модель вписывается заново с сохранением настроек и ориентации.

Освещение: один неподвижный боковой направленный источник, фоновый и ламбертовский вклад. Тени и AO пока не рассчитываются: внутренние поверхности с нормалью к источнику могут оставаться светлыми даже внутри углублений.

В режиме `brightness` яркость усредняется по отсчётам каждой ячейки, затем преобразуется:

```text
mapped = clamp(contrast × (average − 0.5) + 0.5, 0, 1) ^ gamma
```

После этого выбирается символ ближайшей плотности из активной палитры; для классической шкалы задайте `--palette tonal`. Пустой фон всегда остаётся пробелом, в том числе при контрасте ниже единицы. Автоматического растягивания яркости в освещённом режиме нет, поэтому изменение заполнения кадра не меняет контраст. `--contrast 1 --gamma 1` возвращает линейное преобразование яркости.

Sampling сглаживает силуэт и сохраняет вклад мелкой геометрии, но итоговая детализация ограничена сеткой символов. Для более подробной картинки увеличьте модель через zoom или уменьшите шрифт терминала. Ограничение в 16 миллионов внутренних отсчётов предотвращает чрезмерное выделение памяти.

## Палитры и алгоритмы

Атлас задаёт маски и измеренные плотности символов, палитра — допустимые символы, алгоритм — способ выбора. Эти настройки независимы.

| Палитра | Символы | Назначение |
| --- | --- | --- |
| `tonal` | ` .:-=+*#%@` | Плавные тональные поверхности |
| `structural` | Тональная шкала плюс `/`, `\`, `\|`, `_`, `(`, `)`, `[`, `]`, `<`, `>` | Поверхности и направленные штрихи |
| `full` | Все 95 печатных ASCII, требуется `--font` | Эксперименты с буквами, цифрами и пунктуацией |

`brightness` подбирает плотность по средней яркости из активной палитры. `shape` сравнивает восемь яркостей 2×4 с масками кандидатов. При других размерах sampling блок пересчитывается в 2×4 усреднением по площади; при меньшем числе отсчётов новые детали не появляются. Contrast/gamma применяются после общего усреднения в brightness и к каждому значению маски в shape/hybrid. Пустые подобласти остаются чёрными. На почти однородных масках (дисперсия ≤ 0.0025) shape использует подбор по плотности.

По умолчанию включён `hybrid` с `structural`. На плавном участке он выбирает тональный символ по средней яркости маски. Структурные кандидаты доступны возле частичного покрытия, скачка нормали от 25°, нормированной второй разности обратной линейной глубины от 0.05 или второй разности яркости от 0.15. Проверяются также соседние ячейки. Обратная глубина плоскости линейна на экране, поэтому обычный наклон сам по себе не считается разрывом. Кандидат должен улучшать ошибку тонального варианта одновременно на 10% и на 0.002.

Для сравнения форм используется `MSE + complexity_penalty × complexity`: тональные символы имеют сложность 0, структурные 0.25, прочая пунктуация 0.5, буквы и цифры 1. Это предпочтение простого начертания, а не измерение числа штрихов. Полная палитра в гибриде доступна только у границ; в brightness/shape она разрешена во всей модели.

```sh
# Обычный гибрид; эквивалентно запуску без этих двух флагов
cargo run --release -- Skull.obj --object part_0 --rotate-x 180 \
  --glyph-mode hybrid --palette structural

# Классическая тональная поверхность
cargo run --release -- Skull.obj --object part_0 --rotate-x 180 \
  --glyph-mode brightness --palette tonal
```

В shape/hybrid слабый гистерезис удерживает предыдущий допустимый символ, если его ошибка не превышает лучшую более чем на `--stability`. Для тонального выбора сравниваются плотности, для формы — маски. Требуются одинаковое покрытие 2×4, изменение долей покрытия не более 0.01, RMS-изменение яркости до 0.03, изменение глубины до 2% и нормалей до 5°, когда эти признаки доступны. История сбрасывается при изменении проекции, размера, алгоритма, палитры, света или тона. Пустая ячейка сразу становится пробелом; яркость и геометрия между кадрами не усредняются. `--stability 0` отключает удержание.

Каждый внутренний отсчёт имеет собственную глубину. Дополнительные нормали выделяются только для гибридного рендера и принадлежат тем же победившим отсчётам; без них остаётся анализ покрытия, яркости и доступной глубины. Цвет и Unicode не используются. Маска 2×4 ограничивает различимость штрихов; встроенные маски приблизительны.

`M` переключает brightness → shape → hybrid, `P` — палитры. Без шрифтового атласа полная палитра пропускается. В диагностике используется тональная яркость без истории и штрафов; выбранные настройки сохраняются для возврата в shaded.

[Сравнение палитр, PNG-превью и измерения](docs/palettes/README.md). Предыдущий эксперимент со встроенными масками сохранён в [docs/glyph-matching](docs/glyph-matching/README.md).

## Атлас конкретного шрифта

```sh
cargo run --release -- Skull.obj --object part_0 --rotate-x 180 \
  --font tests/fixtures/fonts/JetBrainsMono-Regular.ttf --font-size 16 --glyph-mode shape
```

Для локального шрифта из настроек foot можно использовать `--font "$HOME/.local/share/fonts/JetBrainsMono/JetBrainsMono-Regular.ttf"`. Выбор шрифта явный; настройки терминала автоматически не читаются. `--font-size` измеряется в пикселях на em, а не в пунктах: `size=11` в конфигурации терминала не означает `--font-size 11`.

С `--font` библиотека fontdue растеризует все 95 печатных ASCII-символов в общие ячейки. Без `--font` доступны встроенные маски и шкала для tonal/structural; full отклоняется до открытия терминала. Явные `--font-size` и `--font-cell` требуют `--font`. Необходимы все печатные ASCII и одинаковый горизонтальный advance с допуском 0.01 px; неподходящий или повреждённый шрифт отклоняется до включения raw mode.

Геометрия атласа:

- По умолчанию ширина ячейки — `ceil(advance)`, высота — `ceil(ascent − descent + line_gap)`.
- Дополнительные поля центрируются. Глифы используют общие базовую линию и начало по X, с округлением до пикселя; учитываются индивидуальные смещения bitmap.
- `--font-cell 10x22` явно задаёт размер ячейки. Выходящая за неё часть штриха обрезается; размер самого глифа сохраняется.
- Полная ячейка вместе с полями уменьшается в маску 2×4 через усреднение по площади. Размер точки и положение подчёркивания относительно остальных символов сохраняются.

Атлас строится один раз при запуске и переиспользуется во всех алгоритмах. Смена режима, пауза и resize не растеризуют шрифт заново. Размер ячейки атласа не подменяет геометрию экрана: проекция продолжает использовать `--cell-aspect`, пиксельные размеры терминала или fallback 0.5. Подбирайте размер шрифта и `--font-cell` под фактические параметры терминала; после изменения его шрифта перезапустите просмотрщик с соответствующими настройками атласа.

Калибровка яркости:

```text
density(glyph) = среднее покрытие полной ячейки
ρmax = максимальная плотность в активной палитре
brightness: target = tone(mean(samples)) × ρmax
shape:      target[i] = tone(mask[i]) × ρmax
```

При построении кеша маски всех кандидатов делятся на общий `ρmax`; это эквивалентно масштабированию целевой маски в формуле выше. Гибрид использует один диапазон для тональных и структурных кандидатов. В brightness выбирается ближайшая фактическая плотность. В shape целевая маска сравнивается по MSE только с реальными масками глифов; на почти однородных блоках работает калиброванный выбор по плотности. Порог дисперсии 0.0025 проверяется до масштабирования на `ρmax`. Условные равномерные маски встроенной шкалы в шрифтовом режиме не используются. У каждого глифа сохраняется его исходная плотность: индивидуального растягивания масок нет. Одинаковые ошибки разрешаются в пользу кандидата по плотности, затем по порядку ASCII.

На тестовом JetBrains Mono Regular 16 px/em ячейка получается 10×22, базовая линия — 17, максимальная плотность — около 0.234 (`@`). Поэтому максимальная яркость сцены соответствует самому плотному доступному символу, а не предположению, что он физически заполняет всю ячейку белым.

`M` переключает brightness/shape/hybrid внутри выбранного атласа, `P` меняет палитру без повторной растеризации шрифта. Статус показывает `builtin` либо имя шрифта, px/em и размер ячейки. Пустой фон остаётся пробелом; contrast/gamma по-прежнему обходятся в диагностических режимах. Возможны различия сглаживания между fontdue и терминалом; маска 2×4 также остаётся ограничением точности.

[Атлас, таблица плотностей, сравнения и производительность](docs/font-atlas/README.md).

## Диагностика и клавиши

Все режимы используют одинаковые геометрию, отсечение и буфер глубины:

| `--view` | Что показывает |
| --- | --- |
| `shaded` | Освещение с выбранными contrast и gamma |
| `depth` | Линейную глубину вдоль оси камеры: ближе светлее; диапазон видимых поверхностей отображается в 0.1–1 |
| `silhouette` | Покрытую геометрией область, со сглаженной границей |
| `normal-x`, `normal-y`, `normal-z` | Компоненту нормали в пространстве камеры: −1 тёмный, 0 средний, +1 светлый |

Диагностические режимы используют tonal/brightness и обходят contrast, gamma, штрафы и историю. У плоскости с одинаковой глубиной яркость 0.5; пустой кадр остаётся пустым. Диапазон depth определяется заново по видимым отсчётам каждого кадра, поэтому яркость глубины предназначена для сравнения поверхностей внутри кадра, а не между разными ракурсами.

| Клавиша | Действие |
| --- | --- |
| `1`–`6` | Shaded, depth, silhouette, normal X/Y/Z |
| `+` / `-` | Увеличить / уменьшить zoom в 1.1 раза (`=` тоже увеличивает) |
| `←` / `→` | Азимут света с шагом 5° |
| `↑` / `↓` | Высота света с шагом 5° |
| `,` / `.` | Уменьшить / увеличить контраст на 0.1 |
| `[` / `]` | Уменьшить / увеличить gamma на 0.1 |
| `M` | Переключить brightness / shape / hybrid на текущем ракурсе |
| `P` | Переключить tonal / structural / full (full только со шрифтом) |
| `0` | Вернуть режим, алгоритм, палитру, свет, zoom, contrast и gamma к параметрам запуска |
| Space | Пауза / продолжение вращения |
| R | Сбросить угол автовращения к заданной начальной ориентации |
| Q, Esc, Ctrl+C | Выход |

Параметры изображения меняются и на паузе. Статус показывает режим, `z` (zoom), `c` (contrast), `g` (gamma), `L` (азимут/высоту света), `A` (пропорции ячейки) и краткую подсказку. При узком окне строка обрезается без переноса. В терминале высотой одну строку выводится только статус.

## Конвейер и API

```text
OBJ / встроенная геометрия
  → преобразование модели, камеры и перспективная проекция
  → отсечение по шести плоскостям в однородных координатах
  → растеризация и проверка глубины на каждый внутренний отсчёт
  → интерполяция нормалей с учётом перспективы
  → освещение / выбранный диагностический режим
  → brightness: средняя яркость → contrast/gamma → шкала символов
    shape: маска 2×4 → contrast/gamma → сопоставление глифов
    hybrid: признаки границ → тональная шкала / расширенный подбор
  → слабое удержание допустимого символа (shape/hybrid)
  → ASCII → пакетный вывод через crossterm
  (contrast/gamma обходятся в диагностических режимах)
```

Рендер не зависит от терминала. `geometry` описывает геометрию, камеру и свет; `render` заполняет framebuffer; `ascii` создаёт `CharGrid`; `view` содержит настройки и определение пропорций; `terminal` выводит изображение и статус.

`Camera::fitted` принимает ограничивающую сферу, физический aspect ratio и zoom. `render_with_options` принимает `RenderOptions { mode, capture_features }`; `resolve_with_tone` — `ToneMap`. `resolve_with_options` принимает `AsciiOptions { glyph_mode, tone, palette, complexity_penalty, stability }`; `GlyphMode` независим от диагностического `ViewMode`. `AsciiResolver::with_atlas(GlyphAtlas::from_file(...))` включает калиброванный подбор; сохраняйте resolver между кадрами для кешей палитр, весов sampling и истории; `reset_history()` сбрасывает историю при внешних изменениях сцены или света. Камера и параметры ASCII проверяются автоматически. `GlyphAtlas` предоставляет метаданные, маски, плотности и экспорт PGM/TSV. `glyphs::SHAPE_GLYPHS` содержит встроенные маски в порядке строк (слева направо, сверху вниз), `match_glyph` сопоставляет уже скорректированный массив из восьми яркостей. Старые `resolve` и `resolve_with_tone` сохраняют тональный алгоритм; диагностические framebuffer всегда выводятся тонально. Прямые `GlyphAtlas::select_brightness/select_shape` сохраняют прежний подбор из полного атласа без штрафов и истории. Для расширяемых структур настроек используйте `..Default::default()`. `ViewSettings::effective_tone()` возвращает линейную шкалу для debug-режимов.

Правая система координат: Y вверх, исходная камера смотрит вдоль −Z, глубина после проекции — от 0 до 1. Нормали преобразуются обратной транспонированной матрицей модели. Обратные грани не отбрасываются: открытые поверхности OBJ тоже видимы, а яркость определяется исходной нормалью.

Терминальный слой использует отдельный экран, raw mode, белые символы на чёрном фоне и скрытый курсор. Кадр отправляется одним буфером без очистки экрана между кадрами. При обычном выходе, возвращаемой ошибке или раскрутке стека после panic терминал восстанавливается.

## Проверки и измерения

```sh
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo build --release
python3 tests/terminal_smoke.py
cargo run --release --example benchmark
```

Rust-тесты проверяют растеризацию, глубину, отсечение, нормали, сохранение пропорций при разных sampling, автоматическое кадрирование, tone mapping, debug-режимы, загрузку OBJ и CLI. Unix PTY-проверка на стандартной библиотеке Python проверяет клавиши, паузу, режимы, resize, авто/ручные пропорции и восстановление терминала. Тестовые OBJ созданы для этого проекта.

Для измерений на локальном черепе и воспроизводимых текстовых снимков:

```sh
cargo run --release --example benchmark -- Skull.obj --object part_0 \
  --rotate-x 180 --snapshot-dir docs/readability
```

Benchmark включает рендер и ASCII-преобразование, исключает терминальный I/O и печатает число невырожденных треугольников, время кадра и FPS. Варианты `before` и `after` сравнивают прежние и новые настройки камеры/света/яркости. При сохранении снимков фиксируется исходный ракурс без автовращения.

[Снимки и контрольные измерения на черепе](docs/readability/README.md).

Сравнение алгоритмов глифов на одинаковых геометрии, освещении и ракурсе:

```sh
cargo run --release --example benchmark -- Skull.obj --object part_0 \
  --rotate-x 180 --compare-glyphs --snapshot-dir docs/glyph-matching
```

Этот вариант сравнивает прежние алгоритмы, тональную палитру и гибрид с удержанием и без него. Отдельно измеряются растеризация, преобразование вращающегося и неподвижного кадра; выводится число смен символов. Шаг вращения `--rotation-step` по умолчанию 0.003490659 радиан — 6°/с при 30 FPS. Также сохраняются снимки силуэта и таблица синтетических масок. [Результаты brightness/shape](docs/glyph-matching/README.md).

Сравнение с растеризованным шрифтом, включая время построения атласа, PGM-превью и TSV плотностей/масок:

```sh
cargo run --release --example benchmark -- Skull.obj --object part_0 \
  --rotate-x 180 --compare-glyphs --font tests/fixtures/fonts/JetBrainsMono-Regular.ttf \
  --font-size 16 --snapshot-dir docs/font-atlas/font
```

В benchmark флаг `--font` используется вместе с `--compare-glyphs`. Тестовый шрифт JetBrains Mono v2.304 включён вместе с OFL 1.1 отдельно от лицензии кода.

Для воспроизведения прежнего полного шрифтового подбора:

```sh
cargo run --release -- Skull.obj --object part_0 --rotate-x 180 \
  --font tests/fixtures/fonts/JetBrainsMono-Regular.ttf \
  --glyph-mode shape --palette full --complexity-penalty 0 --stability 0
```

## Дальнейшее развитие

Композиция по мотивам «Сотворения Адама» — демо поверх этой основы. Сначала можно добавить статичный ASCII-фон рук, затем независимо вращающийся череп и слабую пульсацию света. Для объёмных рук с общим освещением понадобятся 3D-модели. Многопоточность, SIMD, тени, AO, блики и восстановление сглаженных нормалей пока не реализованы.
